# Models

This directory contains the ONNX models used by the application.

## YuNet

- **File**: `face_detection_yunet_2023mar.onnx`
  - **Version**: 2023 March (official OpenCV export)
  - **SHA256**: `8f2383e4dd3cfbb4553ea8718107fc0423210dc964f9f4280604804ed2552fa4`
  - **Notes**: This upstream graph mixes static shape hints (Conv_0 expects `1x16x160x160`) with an input tensor declared as `1x3x320x320`. `tract-onnx` refuses to type-check the model because it cannot unify those conflicting dimensions, so the workspace does **not** ship this file as the default for inference.
- **File**: `face_detection_yunet_2023mar_640.onnx`
  - **Version**: 2023 March, re-exported with fixed `640x640` input
  - **SHA256**: `d2c5a887db77802389261b13d2b9f5e1171b9d5787cb315d0add225812ff4d96`
  - **Notes**: Generated by re-exporting YuNet with `input_size=(640, 640)` so every convolution/pooling stage encodes consistent shapes. This sanitized graph loads via `tract-onnx::into_optimized()` and is required for both CLI and GUI builds. To regenerate, export YuNet with OpenCV's `yunet` sample (`--input_width 640 --input_height 640`) or run it through `onnxsim` to freeze the spatial dimensions before copying the file into `models/`.
- **File**: `face_detection_yunet_2023mar_320.onnx`
  - **Version**: 2023 March, same weights with fixed `320x320` input
  - **SHA256**: `024177811019bb600bc7205c26b769917a97048fa18519dc79071024fa279c4f`
  - **Notes**: `onnxsim face_detection_yunet_2023mar.onnx face_detection_yunet_2023mar_320.onnx --overwrite-input-shape "1,3,320,320"` (onnxsim 0.4.36). ONNX Runtime needs it to run a 320 input; the WGSL and CPU graphs only read weights, so they run 320 from either file. Generated by CI for tests and experiment 75, not shipped by releases.

## Eye refiner

- **File**: `eye_refiner.onnx`
  - **SHA256**: `b01dd218b46a7466eb13125b011e81b57e2e2e252794c403029db1d7c7628e76`
  - **Input**: `crop`, `[batch, 3, 112, 112]`, RGB, `(pixel - 127.5) / 128`. **Output**: `eyes`, `[batch, 4]` — two eye points as fractions of the crop side, in the detector's landmark order (index 0 on the viewer's left).
  - **Notes**: Not a detector. It reads a face box somebody else found and replaces landmarks 0 and 1, which is all `fcs-core::face_cropper` uses for eye-line alignment. Trained from scratch on 1,988 hand-clicked eye pairs from the licence-clean Open Images corpus; 1.5 M parameters, opset 12, `Conv`/`Relu`/`GlobalAveragePool`/`Flatten`/`Gemm` only. Against 1,382 held-out test faces it gives **1.18 deg** median eye-line error where YuNet gives 4.05, and 93.3% of faces within 5 degrees against 57.6%. See `tools/dataset/CURVE_RESULTS.md` for the measurement, the generalisation checks, and what is still unproven.
  - **Runtime**: ONNX Runtime only. The built-in CPU graph has YuNet's topology compiled in and the WGSL kernels do not cover `GlobalAveragePool` or `Gemm`, so `EyeRefiner::load` returns `None` without a runtime and callers keep the detector's own landmarks. Releases bundle ONNX Runtime on all three platforms; this fallback is for source builds.
  - **Provenance**: produced by `tools/dataset/train_eye_refiner.py` and exported with a dynamic batch dimension. Unlike the YuNet files it cannot be regenerated from a public URL, so CI and releases fetch it as a release asset and verify the digest above.
